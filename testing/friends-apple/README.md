# Apple native friends session fixture

The `Native Apple friends sessions` workflow runs real Firebase Core/Auth/Database 13.1.1 in an iPhone Simulator app on a standard macOS runner against local Auth and Realtime Database emulators. No real Firebase project, Apple developer membership or signing credentials are used. The executable uses three synthetic identities and the shipping locked database rules.

`tools/private/prepare-friends-apple.py NEW_DIRECTORY` copies the production Swift domain sources and fixture app into an isolated directory and records their checksums. `python3 tools/private/build-friends-apple.py NEW_DIRECTORY` generates an Xcode app project and compiles the actual SDK and domain code for Simulator. Normal ad-hoc Simulator signing uses no developer certificate or paid account. Inside `backend/firebase`, after `npm ci`, run:

```sh
npx firebase emulators:exec --project demo-navi-friends --only auth,database "node tests/native-apple.mjs '/absolute/NEW_DIRECTORY/.build/debug/FriendsNativeProbe' '/absolute/report.json'"
```

The harness requires a demo project, applies the shipping rules to the local emulator and requires a successful native process plus all required named proof flags. It records the actual transcript before asserting. Auth credentials and coordinates are synthetic, and peer data is memory-only. The verified five-proof baseline tests copied native identity with forced token refresh, server cancellation after global pause, synchronous local cleanup preserving the primary identity, a new unauthorized account receiving zero old peer values, delayed account completion after logout, and cleanup after failed setup.

The first actual run 40195746044 proved the missing production session type by failing compilation. Run 40196054447 compiled the implementation but exposed a test-host problem: a bare Mac executable cannot use the normal app Keychain without its app entitlement context (SecItemAdd -34018). The fixture now uses a real Simulator app and the normal Auth SDK; no substitute password storage or Keychain bypass is used. Actual run 40197535444 (source 0cdaa17) passed three native Simulator proofs. Run 40199099843 (source f71d5ed) then passed all five proofs, adding a real delayed session discarded after logout and cleanup after failed setup. The five-proof run used iPhone 17 Pro with the actual pinned SDKs and locked local rules. Run 40222696443 (source a8f4161) passes all six proofs, adding real request delivery/confirmation, independent rights, removal, fresh-session denial after removal, and malformed/self identifier rejection. Run 40224938397 (source 8b53cff) passed all eight proofs, including immutable copied live peer snapshots, independent speed revocation, new-lease freshness and final publication gating. Run 40226300395 (source 1362bd8) passed all ten proofs, adding ACK-gated sharing, pre-ACK sample rejection, omission of unknown speed, and a stored offline pause completed after controller recreation and reconnection. This recreates the controller in one Simulator process; it does not prove physical cold-start persistence. The next twelve-proof candidate adds real online/offline logout and re-login cleanup and has not passed yet. Foreground/background location, map binding, account UI, a device install and friends support in the delivered IPA remain unproven.

SDK prerequisites and public API references: [Apple setup](https://firebase.google.com/docs/ios/setup), [13.1.1 release notes](https://firebase.google.com/support/release-notes/ios), [Auth](https://firebase.google.com/docs/reference/swift/firebaseauth/api/reference/Classes/Auth), [Database](https://firebase.google.com/docs/reference/swift/firebasedatabase/api/reference/Classes/Database).

The public group configuration parser also passed its actual Apple Swift host regression (40199039529, source b20777a): valid iOS/region values accepted and 32 invalid blocks rejected. The host suite ran 50 tests with two explicit skips and no failures. Parser checks do not establish a real cloud connection. Main-target Firebase products/domain sources are registered and the shipping project parses with the real Xcode project model; the complete main-app build with these changes is still required.
