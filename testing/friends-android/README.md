# Native friends integration fixture

This isolated Android application compiles the real production friends sources against Firebase Auth/Database, pinned by BoM 34.19.0. BoM 35's Auth 25 requires API 24, so this compatible stable line preserves the main app's API 23 minimum. The manifest merger caught this before any library override or minimum-version change. It is a test harness, not the Navi package for users. Its application ID is `app.navi.friendstest`; it never reads the `app.navi.private` sandbox or changes that app's signing key/data.

Build with the existing wrapper: `android/gradlew -p testing/friends-android assembleDebug` from the repository root. The small fixture uses cached-compatible AGP 8.11.1 independently of the main application's AGP. Its debug signature uses the existing public CoMaps development key so fixture updates do not require deleting installed test data. No private Navi key is uploaded or used here.

Install the resulting debug APK into the owned test emulator. Start the local `demo-navi-friends` Auth and Realtime Database emulators and load the checked-in rules for that namespace, then run `adb -s emulator-5554 shell am instrument -w app.navi.friendstest/app.organicmaps.navi.friends.FriendsSessionInstrument`. Require `INSTRUMENTATION_CODE: -1` and all five native proof flags. A process exit code alone is insufficient because Android's instrumentation shell can return zero even when a test reports failure.

All identities, passwords, coordinates and accounts are synthetic and local. No Cloud project or real credential is used. Only this test APK permits cleartext traffic to `10.0.2.2`, the Android emulator alias for the host's loopback services. The shipping app's TLS/certificate/network settings are untouched. The fixture does not start GPS or claim a physical drive/background test.

Tests cover copying real authenticated users into independent named data FirebaseApps, actual server cancellation of a permitted native listener, no cached peer values delivered after a switch to an unauthorized account, and cleanup of a delayed session-open result after sign-out. The delayed completion seam still opens a real native SDK session; it controls delivery timing rather than mocking authentication or database permissions.

The production classes first compiled in run 40102063952. Actual native instrumentation from source `ce584e2eb38666650986b3c3d0ca9a695e6dedfc` (build 40114694782) passes all four proof flags and result -1. Copied Auth additionally forces a token refresh. Earlier RED runs exposed unused database initialization during cleanup and the Auth SDK's API-key-shared emulator reconfiguration callbacks retaining deleted apps; the test endpoint is now configured before disposable data sessions, and unused database cleanup does not initialize a Repo. This proves the isolated session lifecycle, not a functioning friends feature.

The host runner `backend/firebase/tests/native-android.mjs` loads the exact rules, checks the owned AVD name, installs only this fixture, and requires all four proof flags and the instrumentation result. Run it inside `firebase emulators:exec`, with `NAVI_TEST_ADB` pointing to the installed SDK adb executable. Its APK and report arguments are explicit paths. Neither this runner nor a passing build configures a real cloud backend.

Build 40115180545 additionally passes `native_friend_actions` using the production `FriendsRepository`. Requests alone cannot read profiles, confirmation requires an incoming request, position/speed/trip rights remain explicit, and removal deletes own consent and grants atomically. The host runner now requires this fifth proof as well.
